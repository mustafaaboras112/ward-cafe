# كافيه ورد

## الصفحات

- `index.html`: اختيار الطاولة والمنيو والسلة ومتابعة طلبات العميل.
- `waiter.html`: متابعة الطلبات وتأكيد التوصيل ونقل/تفريغ الطاولات.
- `kitchen.html`: تجهيز الطلبات وتحويلها إلى «جاهز».
- `pos.html`: تحصيل الحساب نقداً أو تسجيل الدفع الذي تم على جهاز البطاقة، وطباعة الفاتورة.
- `accounting.html`: المبيعات المدفوعة والمصروفات والذمم وإقفال الوردية.
- `admin.html`: إضافة الأصناف وحذفها وتعديل الاسم والسعر.

لكل صفحة ملف في `js/` وملف في `style/`. يحتوي `js/common.js` على الوصول المشترك للبيانات ومعاملات الطلبات والطاولات والمساعدات العامة، و`firebase-config.js` على الاتصال فقط. ملفات JavaScript القديمة لا تحتوي على منطق تنفيذي ولا تستخدمها الصفحات.

## تدفق العمل

1. يُحفظ طلب العميل وحجز الطاولة معاً، وتظهر «طلبك قيد التحضير».
2. المطبخ يضغط «تم تجهيز الطلب». يصل تنبيه للكارسون وتظهر للعميل «طلبك في طريقه إلى الطاولة».
3. الكارسون يؤكد «تم التوصيل» بعد التسليم الفعلي.
4. الكاشير يختار الطاولة ويؤكد استلام الدفع. يمنع التحصيل عند وجود طلب لم يُسلّم، أو مبلغ نقدي ناقص، أو صندوق مغلق.
5. تُحفظ حالات الدفع والمبيعات معاً. معرّف البيع مطابق لمعرّف الطلب لمنع تكراره.
6. يفرّغ الكارسون الطاولة بعد مغادرة العميل. يمنع التفريغ طالما يوجد طلب غير مدفوع. يمكن تحرير الحجوزات القديمة التي لا تحتوي على طلبات مفتوحة.

«تفريغ» يعني إنهاء حجز الطاولة، وليس تقسيم الفاتورة. النقل ينقل جميع الطلبات المفتوحة إلى طاولة متاحة مع الحفاظ على معرّفاتها ومتابعة العميل والمبالغ.

متابعة العميل مرتبطة بمعرّف جلسة تبويبه ومعرّفات طلباته، وتستمر عند تحديث الصفحة أو نقل الطاولة. فتح تبويب أو جهاز جديد لا يستعيد طلبات الجلسة السابقة تلقائياً.

## التشغيل والتحقق

قدّم مجلد المشروع عبر خادم HTTP محلي أو الاستضافة، وافتح `index.html`. إعداد Firebase الحالي موجود في `firebase-config.js`.

عند إعداد Firebase، لا تتحول عمليات الحفظ الفاشلة إلى عمليات محلية ناجحة، ولا توجد مزامنة تلقائية لطلبات offline. التخزين المحلي متاح فقط عندما لا يكون Firebase معدّاً، وهو خاص بالمتصفح ولا يربط الأجهزة المختلفة.

العمليات المترابطة تستخدم transaction على جذر Realtime Database للحفاظ على اتساق الطلبات والحجوزات والمبيعات. يلزم تحقق قواعد القراءة والكتابة الفعلية لهذا المسار؛ لم تُعدّل القواعد أو البيانات السحابية ضمن هذه التغييرات. هذا التصميم يحافظ على بنية البيانات الحالية، لكنه يقرأ الجذر وقد يحتاج خدمة خلفية أو إعادة تنظيم البيانات عند التوسع.

رمز الواجهة الموجود هو `1234` للإدارة والمحاسبة والكاشير. هذا قفل واجهة محلي وليس Firebase Authentication أو صلاحيات خادم؛ يلزم ضبط المصادقة والقواعد المناسبة قبل تسليم استضافة عامة، ولا تفتح قواعد قاعدة البيانات للعامة.

اختبارات محلية بلا اعتماديات إضافية:

```sh
node tests/workflow.cjs
```

تغطي الاختبارات تدفق الطلب والنقل والدفع والتفريغ، منع تكرار الدفع والتحصيل المبكر، فشل الحفظ، رسائل العميل وعزلها بين الجلسات، وتهيئة الصفحات وروابط ملفاتها. تستخدم تخزيناً محلياً ومحاكاة معاملات Firebase؛ لا تتصل بقاعدة الإنتاج.

التحقق اليدوي المتبقي: افتح الصفحات الست على أجهزة تجريبية مع Firebase تجريبي وقواعده الفعلية؛ جرّب طاولة 12 ثم النقل إلى 18، الطلبات المتعددة، التنبيهات بعد تحديث الصفحة، رفض الاتصال، الدفع مرتين من كاشيرين، وطباعة الفاتورة على الهاتف وسطح المكتب. لم يتوفر متصفح متصل لإجراء التحقق المرئي في هذه الجلسة.
