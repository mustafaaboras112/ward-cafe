# تشغيل Ward Cafe على XAMPP وMySQL

هذه النسخة تستخدم جهازًا رئيسيًا داخل المقهى لتشغيل MySQL وخادم Node.js. أجهزة الكاشير والمدير والتابلت لا تحتاج XAMPP؛ تفتح النظام من المتصفح عبر شبكة Wi‑Fi المحلية.

## المتطلبات على الكمبيوتر الرئيسي

- Windows 10 أو 11.
- XAMPP مع MySQL/MariaDB.
- Node.js 20 أو أحدث.
- اتصال جميع الأجهزة بنفس الشبكة المحلية.

## 1. تجهيز قاعدة البيانات

1. افتح XAMPP Control Panel وشغّل **MySQL**.
2. افتح phpMyAdmin من XAMPP.
3. نفّذ الملف `server/sql/schema.sql` لإنشاء قاعدة `ward_cafe` والجداول.
4. نفّذ `server/sql/seed.sql` لإضافة المنيو الابتدائي. يمكن تعديل الأصناف لاحقًا من لوحة الإدارة.

الإعداد الافتراضي في XAMPP عادةً هو المستخدم `root` بدون كلمة مرور. إذا غيّرت ذلك، حدّث ملف `.env` في الخطوة التالية.

## 2. إعداد الخادم

افتح PowerShell أو CMD داخل مجلد `server` ثم نفّذ:

```bat
copy .env.example .env
npm install
npm run setup-admin
npm start
```

`npm run setup-admin` ينشئ أول مدير فقط عندما لا يوجد مدير مسبقًا. اختر رقم مستخدم من 4 إلى 12 رقمًا وكلمة مرور قوية لا تقل عن 8 محارف.

## 3. ملف .env

مثال مناسب لـ XAMPP الافتراضي:

```env
HOST=0.0.0.0
PORT=3000
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=
DB_NAME=ward_cafe
SESSION_HOURS=12
TRUST_PROXY=0
COOKIE_SECURE=0
```

لا ترفع ملف `.env` إلى GitHub ولا تضع فيه كلمة مرور يمكن مشاركتها.

## 4. اختبار الجهاز الرئيسي

بعد ظهور:

```text
Ward Cafe: http://localhost:3000
```

افتح:

- `http://localhost:3000/login.html`
- `http://localhost:3000/api/health`

يجب أن يعيد health قيمة `database: connected`.

## 5. فتح النظام على أجهزة المقهى

اعرف IPv4 للكمبيوتر الرئيسي بتنفيذ:

```bat
ipconfig
```

مثال: إذا كان العنوان `192.168.1.10`:

- الكاشير: `http://192.168.1.10:3000/pos.html`
- المدير: `http://192.168.1.10:3000/admin.html`
- المحاسب: `http://192.168.1.10:3000/accounting.html`
- تابلت الجرسون: `http://192.168.1.10:3000/waiter.html`
- تابلت المطبخ: `http://192.168.1.10:3000/kitchen.html`

إذا لم تفتح الصفحات من التابلت، اسمح لـ Node.js أو المنفذ TCP 3000 عبر Windows Firewall للشبكات الخاصة فقط.

## 6. الصلاحيات

- `admin`: الإدارة الكاملة.
- `cashier`: الكاشير والتحصيل وشاشة الجرسون عند الحاجة.
- `accountant`: المحاسبة.
- `waiter`: شاشة الجرسون.
- `kitchen`: شاشة المطبخ.

الصفحات المحمية لا تعتمد على إخفاء الأزرار؛ الخادم يتحقق من الجلسة والدور قبل إرسال الصفحة وقبل تنفيذ عمليات API الحساسة.

## 7. تدفق اختبار يدوي

1. سجّل دخول كمدير وأنشئ مستخدم مطبخ وجرسون وكاشير.
2. افتح الصفحات الثلاثة على أجهزة/متصفحات مختلفة.
3. من الكاشير افتح طاولة وأرسل طلبًا.
4. تأكد أن الطلب يظهر في المطبخ.
5. من المطبخ اختر «تم تجهيز الطلب».
6. تأكد أن الطلب يظهر جاهزًا لدى الجرسون.
7. من الجرسون اختر «تم التوصيل».
8. من الكاشير حصّل الحساب نقدًا وبطاقة في تجربتين منفصلتين.
9. جرّب نقل طاولة قبل الدفع.
10. تأكد أنه لا يمكن الدفع قبل التوصيل.
11. تأكد أنه لا يمكن إغلاق اليوم مع طلب غير مدفوع.
12. بعد إغلاق اليوم، تأكد أن الخادم يرفض دفعًا أو مصروفًا جديدًا لذلك اليوم.

## ملاحظات تشغيلية

- MySQL هو المصدر الرسمي للبيانات في هذه النسخة.
- التخزين المحلي في المتصفح يستخدم كنسخة قراءة مؤقتة فقط عند فقد الاتصال، ولا يسجل عملية دفع ناجحة أو طلبًا رسميًا بدون الخادم.
- يفضّل تثبيت عنوان IP ثابت للكمبيوتر الرئيسي من إعدادات الراوتر قبل الاستخدام اليومي.
- قبل البيع التجاري، أضف نسخًا احتياطيًا يوميًا لقاعدة البيانات وسجل عمليات إداريًا.
